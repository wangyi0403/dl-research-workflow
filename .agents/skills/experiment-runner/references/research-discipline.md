# Research Engineering Discipline

## Preserve the experiment contract

Use the project directory boundaries and immutable Experiment IDs. Keep configurations, failed runs, search histories and checkpoints that support a reported decision. Generated packaging can be cleaned only within the user's authorized scope and recovery plan; a negative result is not dead code.

## Fair comparisons

Control data access, leakage, selection and reporting. Match tuning and compute opportunities to the scientific comparison; identical optimizers, hyperparameters or parameter counts are not universally fair across model families. Include strong simpler controls when they can falsify a complexity or mechanism claim.

## Resources and execution

Estimate memory from actual smoke measurements, leave suitable headroom, and use only the authorized allocation. Parallelism is a resource choice, not a mandatory default. Test decisive assumptions early; do not follow a fixed run order when a cheaper test can invalidate the method.

Distinguish soft budget checks between runs from an enforced job/process timeout. Record exactly which process may be stopped and preserve its logs and partial outputs. A completion message without exit status and expected artifacts is insufficient.

## Failure and continuation

Diagnose from evidence before changing code. A new repair uses a new immutable run/config ID and links the failed attempt. Count repairs cumulatively for the same fault and stage; obey Gate failures and the project budget. Do not alter the objective or optimize until a favorable metric appears. Scientific value is judged from the problem and evidence, not fixed novelty scores or a requirement to beat SOTA.
