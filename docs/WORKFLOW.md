# 阶段与 Gate 工作流

本文件保存 Stage 0–6 与 Gate A–F 的详细执行规则。项目常驻规则和读取路由见 `../AGENTS.md`；只读当前阶段及相关 Gate，不要全文加载本文件。项目状态唯一入口为 `00_start.md`，编号文档和 `docs/README.md` 说明产物归属。

## Stage 0：范围与初始化

填写 docs/00_start.md，冻结问题、成功标准、数据、预算、交付与权限，记录环境与治理事实。

区分用户约束与待验假设；初始想法不证明新颖性。

## Stage 1：证据、想法、方法与设计

主控 Agent 负责研究推进、事实记录与验收；在项目授权内，可与用户建立并选定高能力模型的 外部 AI 协作会话共同完善方案、辅助推导或攻克关键难题。按[项目协作约定](AI_COLLABORATION.md)批量准备问题与必要证据，在方案节点集中交接，不要求每个子阶段都调用，也不自动追加第二顾问。会话、授权引用、请求预算与交接状态只维护在 00_start；核验后的研究决定写回本阶段对应文档。

### 1A：数据分析与 Running Example

提出方法前先使用 $research-data-audit 检查已有数据。在 docs/01_data_analysis.md 记录模式、单位、缺失、泄漏风险、划分边界、类别平衡、时空结构和具代表性的 Running Example。

### 1B：期刊调研

当目标期刊会实质影响范围或报告方式时使用 $journal-scout。先广泛收集，再由用户缩小候选列表，随后核验当前 scope、作者指南、文章类型、限制、数据/代码政策及近期相关工作。结果写入 docs/02_journal_scouting.md。期刊的具体要求优先于通用写作偏好。已有目标或修稿来信时复用已有选择，只核对受影响要求；以来源、版本与要求 ID 登记实际期刊/编辑要求，区分 docs/WRITING_STANDARD.md 的个人默认与历史参考意见。

### 1C：研究构思

使用 $research-ideation 生成有文献依据的想法。完成“研究问题卡”，建立检索/证据图，识别边界条件，生成多个候选方案，检验新颖性，检查数据和算力可行性，在安全时运行最小有用本地试验，并保留备选方案。在 docs/03_idea_report.md 记录候选、拒绝理由、风险和选定方向。

工程研究先填写 docs/03_idea_report.md 的“工程—科学贡献链”：从有实际后果的现场问题和既有工程瓶颈，提出可迁移的测量、物理或推断问题；方法是检验载体。可观测量、干扰因素、假设机制和可证伪预测未明确时，只能称经验或表征假设，不得宣称物理贡献。

承诺研究想法前运行 Gate A。先检查阻断项：若已有 Evidence ID 支持的基线、消融或简单控制已合理否定核心机制，则将当前方案记为 reject 或 pivot，不得以更多算力或乐观阈值粉饰；未测试不等于已证伪。通过要求：问题有实质性、证据缺口可信、论断可检验、数据路径明确、方案可行、必要时适配目标期刊，并有清晰备选。对于工程研究，还须确认现场价值、工程瓶颈、机制问题、可迁移认识和双重验证链均已记录。失败时回到检索、缩小范围、更换论断或更换想法。

### 1D：方法细化

使用 $research-refine 形式化问题、假设、符号、最小充分机制、模块、技术路线、与既有工作的差异、预期失效模式和资源风险。写入 docs/04_methodology.md，并维护“局限—思路—挑战—机制—验证链”。每个工程方法须明确它检验的机制命题、可迁移设计原则和工程/科学两条验证路径；没有论断或诊断目的时不得新增模块。

### 1E：实验规划

若项目复现或扩展已发表方法，先按当前会话可用能力查找复现流程；缺少专用 Skill 时，用 AgentHub 查询 `paper-reproduction`，核验技能和依赖，并仅在授权范围内安装到本项目。随后在 docs/reproduction/<paper-key>/ 创建带证据标记的复现契约，再纳入基线与实验计划；不得把查看仓库代码当成复现成功。

使用 $experiment-plan 将每项论断映射到数据集、基线、指标、统计检验、消融、稳健性检查、误差分析与失败即停顺序。工程研究至少包含双重验证：工程任务是否得到改善，以及机制命题或可迁移设计原则是否被干预、反事实、跨条件或外部数据支持。外部数据只在其测量/推断问题可比时用于检验迁移性，不能作为装饰性泛化。主实验前先创建 docs/05_experiment_plan.md、docs/06_result_tables.md 和 docs/07_experiment_tracker.md。

运行 Gate B。通过要求：无泄漏划分及训练内拟合、验证集选模与最终测试使用规则、有意义且公平的基线、预先明确的主指标与纳入规则、不确定性/统计处理、可复现配置、成本上限、负结果解释和明确决策规则。具体评价协议写在 05，表结构和统计定义在 06 引用，不维护两份协议。

## Stage 2：执行与分析实验

### 2A：环境与 smoke test

确认本地/项目环境，不得假设存在全局 Conda 环境。核验数据访问、单批次前向/反向、指标实现、检查点与日志路径、随机种子处理和估计成本。使用远程或付费 GPU 前取得明确授权。

### 2B：按计划执行

实验由 主控 Agent直接执行，或分派给边界明确、互不冲突的子代理；仅在用户明确要求时新建独立 Codex 任务。具体模型档位按全局分工规则及当前可用能力选择。交接提供目标、相关 Claim/Experiment ID、文件范围、资源上限、停止条件和验收要求；执行者返回产物与验证证据，主任务核验后整合。共享工作区避免同时修改同一文件，实验调度者仍保持唯一。普通运行状态不逐条发给 ChatGPT；只有足以改变方案的发现或关键阻塞才考虑集中交接。

仅在 Gate B 之后使用 $experiment-runner。按记录顺序执行；每次实际运行创建新的不可变实验 ID，即使配置相同；采集日志与结构化输出，并持续更新统一台账。实验启动后依 docs/07_experiment_tracker.md 的来源与冲突规则刷新 active-run：运行字段为 CSV/state.json 的派生绑定，监督优先读取该入口，必须内嵌字段时标注来源及核对时间；健康检查通过后再绑定已授权监督。公共台账及绑定只由主任务或唯一调度者串行更新。仅在用户明确要求时创建 Goal，不得为等待或交接把未完成 Goal 标为 complete。每条实验链只保留一个调度者；先核验现有监督，再依控制器接口完成接管，不能关闭唯一唤醒机制后才准备接管。heartbeat 对 RUNNING 无变化保持静默；终态或异常空闲后推进已授权的分析、修复或下一阶段，不把启动或等待当作完成。重试前先诊断；同一故障、同一阶段累计最多三次有新证据的修复尝试，不因新实验 ID 或交接重置次数，超限停止该路径并取得追加授权。不得隐藏失败或空结果。

### 2C：分析

依据 results/data、日志和实验台账编写 docs/08_analysis.md。说明分析单位；报告中心估计、不确定性、跨种子波动、失败案例、稳健性、信念更新、下一步、产物来源和论断影响。隔离尚未解决的矛盾统计结果。区分探索性与验证性分析。完成主结果后使用 $result-to-claim，将每项 Claim ID 结论标为 promote、weaken、reject 或 collect-more-evidence；工程价值和机制/科学价值分别判断。

运行 Gate C。通过要求：运行与分析符合已冻结协议或已明确披露偏离，分析单位与不确定性有效，结果可追溯，矛盾已解决或隔离，各项论断与证据强度一致。失败必须明确路由：协议错误则修复后重跑，无效比较则修复设计，证据不足则弱化论断，想法失败则回到 Stage 1。设计或协议改变时先重验受影响的 Gate A/B，再执行依赖它们的新实验。

## Stage 3：叙事、图与表

### 3A：论文计划

使用 $paper-plan 定义论文类型与叙事轴、中心论断、贡献链、章节逻辑、Running Example、证据位置、图表计划、局限和目标读者路径。工程论文将叙事组织为“现场问题及后果 → 既有工程路径的瓶颈 → 可复用的测量/物理/推断问题 → 经证据支持的设计原则或认识 → 作为载体的具体方法 → 工程与科学双重验证”。不得把采用某个模型、模型家族或模块堆叠本身写为中心贡献。写入 docs/09_paper_plan.md，并在完整写作前运行 Gate D。benchmark/evaluation 类型额外核验评价缺口、构建流水线、覆盖/污染风险、评价协议和能力边界；不得为凑完整性强加 companion method。

按 docs/WRITING_STANDARD.md 实化用户七章偏好与逐章字数/图表预算；在 09 记录项目采用值、计数口径与合理偏离。期刊或已批准稿件结构另有安排时保留其要求，不机械重排；参考配额不足以授权新实验或补造证据。

09 的叙事追踪矩阵将必要支持论据连接到读者问题、精确读数、替代解释和缺口；图、表、公式或算法由表达用途选择。论证顺序不依项目时序，主文与补充材料按解释重要性分配，缺证据回到 05 的决定性实验或收窄论断。

Gate D 通过要求：论文类型与中心论断匹配，贡献与最近工作差异有证据，章节及图表能够承载所需证据，允许措辞与 Claim 状态一致，重要局限和目标期刊约束有明确位置，项目章节功能、预算及适用编辑要求已安排。

### 3B：图与表

数据图使用 $scientific-figure-making，概念图或方法图使用 $paper-illustration。每张定量图都必须可从 results/data 复现；绘图代码与图放在一起。为每张图声明叙事角色（动机、方法总览、实验或支持），并检查其 Claim/Chain ID、Running Example、命名与正文一致。检查尺度、不确定性、图例、色彩可访问性、印刷尺寸以及与表和正文的一致性。写入 docs/10_figure_report.md，并运行 Gate E。

按 docs/WRITING_STANDARD.md 检查短题、面板说明、必要 Notes 和正文长解释的分工；适用编辑要求引用 02，在 10 记录当前版本位置与检查结果。保留独立阅读所需的单位、统计定义和编码说明。

Gate E 通过要求：定量图表可由记录的输入与代码复现，来源和 Claim/Chain 可追溯，编码与不确定性呈现准确，图表与正文一致，题/Notes/解释位置适当，并通过实际稿件显示尺寸下的视觉检查。

首次完整起草前，若仅剩依赖尚未形成正文的图文一致性检查，可记录 Gate E 为 CONDITIONAL：科学有效性、来源、可复现性、图表本身和必要视觉检查必须已通过，逐项写明材料版本、待办、负责人及“成稿后、Gate F 判为 PASS 前”的关闭条件；仅允许起草和内部修订，禁止最终交付。关键科学证据 unknown 或阻断项 fail 不适用此路径。成稿后在 E 原记录关闭待办，F 引用有效记录而不重复执行相同检查；版本变化按既有规则重验受影响项。

## Stage 4：中文审稿轮次到英文 LaTeX

Gate D 通过、关键证据/数值/图表/引用来源就绪，且 Gate E 为 PASS 或满足上述条件起草路径的 CONDITIONAL 后使用 $paper-write；成稿后复核并关闭延后的 E 项，再完成 F，缺口不得用流畅正文补齐。默认从已批准计划写中文 v1，经用户 Round 1 审结构/论证/证据、Round 2 审措辞/术语/图表/局限后再产出英文 LaTeX；用户或期刊另有语言流程时从其要求。

写作可由 Codex 完成，也可在授权内由 外部 AI 协作者 起草或实质性重写。Codex 先完成证据骨架，在 09_paper_plan 的交接项中引用已确认论断、推导、图表、数值与引文来源、章节逻辑和稿件版本，再集中提交足以成稿的材料。该次请求明确切换为作者角色，直接交付可整合正文，材料缺口和编辑说明另列；既有人工审阅与语言安排不变。Codex 取回后核验科学含义、公式、数字、引用和跨章节一致性，整合到本地并验证编译。作者起草和关键意见复核相互补充，模型意见不替代证据或负责人确认。

成稿与集中修订是可选的整批交接节点，不按段落频繁续发，也不以重复催促获取回复；请求预算与读取等待遵循全局协作规则。纯语言润色复用已有证据记录，只有新增科学论断或改变结论时才复核受影响证据，不重启完整研究审计。

使用 $academic-humanizer 改善学术表达和论断—证据对齐，不以 AI 检测分数为目标。先恢复作者判断，在论断本身校准条件和模态，清理无证据的自我否定与先宣称再撤回，保留真实局限、范围条件与不确定性。局限说明实际证据及对结论的影响，后续检验只在已有、用户要求或适用编辑要求时纳入，不凭空补造。遵循目标期刊真实作者指南；不得强加通用参考文献数量、第一人称禁令、斜体禁令或固定出版社模板。

写作与集中交接同时遵循 docs/WRITING_STANDARD.md、09 的项目预算及 02 的适用编辑要求；结论包含研究回答、认识、应用意义与具体后续检验，不仅复述结果。成稿后更新 09 的实际计数和偏离理由，检查标题、简称、文章自指、时态及图题/Notes 分工，不以凑配额代替必要内容。

按相关科学问题综合最近工作，核对公平比较、独立重复与不确定性语义。标题、摘要、引言、主要展示和结论使用同一 Claim 状态；相关章节按需读取 paper-write 的段落、相关工作、实验和讨论指南，局部语言编辑不重跑全流程。

深度审查前运行 Gate F。使用 $citation-verification 和 $claim-numerics-audit，将结果记录在 docs/11_pre_submission_audit.md。通过要求：稳定的目标语言源文件、完整证据链接、数值一致、已核验引文、已声明局限、已关闭依赖成稿的 Gate E 待办、写作结构与适用编辑格式已核验、按目标机构或期刊要求确认的 AI 使用/披露状态，以及可编译稿件。一般预算偏离有依据即可记录，不独立阻断科学 Gate；最终投稿前真实硬限制和适用编辑要求须闭环。

## Stage 5：深度审查与修订

使用 $paper-audit，按风险选择编辑、方法学、领域、批判/对抗、文献和先前技术等审查维度；这些维度不对应固定人数或固定调用次数，重要科学判断保留必要的独立复核。合并重复问题；问题的 severity 统一为 major、moderate 或 minor，type 区分 issue 与 suggestion，不把 Suggestion 当作严重程度。major 影响科学有效性或核心结论，moderate 影响解释或可复现性，minor 是局部且不改变结论的问题；suggestion 表示可选改进，不能用此类型弱化实质缺陷。审稿与修复角色尽量分离。

需要 外部 AI 协作者 参与时，按授权和剩余请求预算，将已核验的问题、对应证据、冻结决定与当前稿件合并为一次明确的审查或集中修订交接。若它参与起草，由主控 Agent 复核关键论断与证据，不能仅靠同一模型自审；实质分歧回到来源或最小必要验证。外部协作不另起一套审查轮次，达到本阶段停止条件后不继续互相挑错或重写。

最多进行四轮基于证据的迭代。修改证据、数值、方法或图表后，按下方依赖变更规则重新核验受影响的 Gate A–F，并在 docs/11_pre_submission_audit.md 记录所审稿件版本；PASS 仅绑定经过核验的输入。主要问题解决后可提前停止；质量评分或问题长期停滞时，把取舍升级给用户，不得无限重写。科学有效性、证据、统计及复现性优先于写作启发式。

审查报告仅在 Stage 5 实际开始后写入 paper/review_notes.md；实验决策与偏离记录在 docs/07_experiment_tracker.md。

真实审稿回复在同一问题记录逐项对应回应、实际修改位置和受影响核验；当前源文件或渲染稿支持“已修改”后才使用完成措辞。对有据异议专业回应，材料不足记待解决，不能以新增泛泛局限或未经确认的未来工作代替科学修复。

## Stage 6：投稿与发布准备

仅在目标期刊与稿件稳定后使用 $cover-letter。核验作者信息、scope、文章类型、格式、篇幅、图表引用、参考文献身份、数据/代码声明、利益冲突、经费、伦理和补充材料。准备 paper/cover_letter.tex 或期刊要求的格式。

使用 $research-publication 准备本地、可审阅的发布就绪包：明确公开/受限资产、许可与归属、脱敏检查、复现命令、版本和校验和、数据/模型卡及已知局限。将清单与例外写入 `docs/12_release_readiness.md`；它只准备和审阅，不上传、不创建 DOI、不改变仓库可见性。

外部投稿、仓库发布、DOI 创建、模型/数据上传和发送邮件始终需要用户明确授权。

## Gate 协议

按风险选择审稿视角；重要 Gate 使用多个相互独立的本地视角，窄而低风险的检查不强制固定人数。审稿者得到产物与 rubric，不预知预期结论或他人意见；有证据的少数意见不得因票数被丢弃。每项发现标为 pass/warn/fail/unknown，记录证据、影响、负责人、下一步与回滚；总体决定为 PASS/CONDITIONAL/FAIL。记录所审产物的版本/哈希与日期。CONDITIONAL 必须列出可继续范围、待办及到期触发条件；关键证据 unknown 或阻断项 fail 时，不得进入依赖该条件的实验或交付。Gate 记录写在所属编号文档，00_start 只链接，不复制结论。

### 依赖变更与 Gate 失效

只重验受影响项，保留不受影响记录。变更发生后在所属 Gate 记录中注明旧结论的适用版本、失效范围与替代记录；受影响项完成复核前，不继续依赖其旧 PASS 的工作。

| 变更 | 首先重验 | 后续影响 |
|---|---|---|
| 研究问题、核心机制、新颖性或关键可行性证据改变 | A（03） | 若改变方法与验证目标，继续重验 B 及受影响下游项 |
| 数据版本/划分、训练或测试使用、基线、主指标、选模或统计协议改变 | B（05） | 先完成数据审计及协议修订，再运行依赖新协议的实验；已有结果重验 C |
| 新实验、分析修正、证据冲突或论断强度改变 | C（08） | 更新 03 Claim 状态，并重验受影响的 D–F |
| 论文类型、贡献组织或证据位置改变 | D（09） | 重验受影响的 E/F |
| 图表数据、生成代码或视觉表达改变 | E（10） | 涉及数值/解释时同时重验 C，更新 F |
| 稿件、引文、数值或披露改变 | F（11） | 若暴露上游问题，按本表回到相应 Gate |

## 上下文交接

阶段切换、运行启动/终态、阻塞或授权变化时更新 docs/00_start.md 状态表与相关正式产物。交接引用现有记录，不另建平行状态文件；不能用缺少运行对象的空监督替代下一步。

恢复先读 docs/00_start.md，再按其中链接读取当前阶段产物及未决 Gate；Stage 5 同时读取 paper/review_notes.md 和所审稿件版本。

长任务恢复或交接按 00 的“最近恢复核对”比较下一动作与冻结问题、成功标准、05 协议及产物版本；实质偏差按上表处理，只暂停受影响路径。实验批次汇总按 06 的预定运行集合核验覆盖；只有已完成运行的表格不能证明计划批次齐全，排除与重跑决定保留在 07。

## 完成检查

宣布某个阶段完成前，核验必需文件存在、论断与证据一致、本阶段确有要求的审批已记录且覆盖当前对象/版本、复现字段已填充，并明确下一 Gate 或备选路径。不要求每阶段新增批准，执行或算力授权不替代最终科学结论签认。初始化、变更 Skill 和发布准备前运行 `python tools/project.py check <project-path>`。
