# 06 结果表

主实验前定义表格骨架及分析约定。本文件维护表结构、指标定义与来源索引；填好表头不表示已有结果。

| Table ID / Claim ID | 行列与指标（单位、方向） | 分析单位、种子合并与不确定性方法 | 纳入/排除规则 | 输入数据与 Experiment ID | 生成命令与输出路径 |
|---|---|---|---|---|---|

模板附带 `experiments/scripts/build_result_tables.py`。论文使用时先运行 `python experiments/scripts/build_result_tables.py --project . --strict --metric NAME --dry-run` 核验输入；把 NAME 换成预先指定的必需指标，多个指标重复传入 `--metric`。核验通过后去掉 `--dry-run` 生成 `results/tables/run_metrics.csv`。自定义 `--output` 也只能指向项目 `results/tables/` 下的 CSV，不可覆盖源结果。

批次表按 05 的预定纳入规则提前列明所需 Experiment ID，在命令中逐项添加 `--expect-run EXPERIMENT_ID`；例如 `--expect-run E-001 --expect-run E-002`。此选项只选择明确列出的运行，要求每项在台账中唯一且 COMPLETE，并通过指标与溯源校验；缺失、失败、未完成或与 `--claim-id` 冲突会阻止输出。预期集合从实验计划与台账的对应关系生成，不能从已完成或表现较好的运行反推；合规重跑的替代 ID 与排除依据记录在 07 后再更新集合。未传此选项时会明确提示未检查批次覆盖，即使严格溯源通过也不能宣称计划齐全。

脚本按实验台账中的 COMPLETE 记录读取 `result_path` 指向的 JSON 结果，要求其中包含非空的数值型 `metrics` 对象。每行对应一个运行，保留 Claim、数据版本、划分、种子、配置哈希和结果哈希。严格模式要求溯源字段完整、当前配置与记录哈希一致、结果与运行完成时冻结的哈希一致，且每行都包含指定的必需指标；未声明预期集合时失败或未完成运行仍会跳过。脚本不跨种子求均值、不计算区间或显著性；运行 ID 齐全也不替代方法、数据集与种子设计的科学审查。

结果哈希来自 CSV 的 `result_sha256`，或 runner 终态 `state.json` 的 `output_hashes`；`state_path` 可显式指向该状态文件，未填写时读取 `log_path/state.json`。若状态文件存在，还会核验实验 ID、COMPLETE、退出码、配置哈希及冻结结果哈希的一致性。外部调度器须在运行完成时记录 `result_sha256`；缺少原始冻结记录的旧运行不能事后对当前文件补算哈希并声称已验证原始证据，应记录缺口并从可信原始记录恢复或重新运行。

不使用 `--strict` 的探索模式会提示未验证冻结溯源，缺失指标可留空但不补成零；该输出不能直接作为已核验的论文表。

主实验前仍须在上表定义分析单位、纳入规则、指标和统计方法。论文汇总如需均值、置信区间、配对检验或特定分组，应按本项目的预注册计划实现相应汇总脚本，不能把 run-level CSV 直接解释为统计结论。输出文件默认拒绝覆盖；确认旧结果可替换时显式传入 `--overwrite`。使用命令及输出路径记录在本表。

重新运行生成命令并核对样本数、实验 ID、关键指标及不确定性后，才引用进论文。若需要在本文件展示数值，使用生成内容并标明来源版本，不手工维护另一份数值表。08 保存解释与决策；03 维护 Claim 当前状态。
