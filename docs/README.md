# 阶段文档索引

本目录保存科研项目的编号产物。先读取 `00_start.md`，再按项目根目录 `AGENTS.md` 的按需路由确定当前 Stage 和最小读取集；阶段/Gate 判据以 `WORKFLOW.md` 为准。不要把未核验内容写成已完成事实。

| 文件 | 用途 |
|---|---|
| `WORKFLOW.md` | Stage 0–6、Gate A–F、失败路由、交接与完成条件；只读当前阶段所需部分 |
| `WRITING_STANDARD.md` | 用户七章默认、篇幅与图表参考配额、标题/摘要/图注/结论及格式验收；规划/写作/投稿时按需读 |
| `00_start.md` | 研究问题、范围、数据边界、算力、授权和交付物冻结 |
| `01_data_analysis.md` | 数据来源、版本与哈希、模式、质量、划分与变换、Running Example |
| `02_journal_scouting.md` | 目标期刊/venue 的 scope、作者指南和相关工作 |
| `03_idea_report.md` | 研究问题卡、证据图、候选想法、查新、Pilot 和 Gate A |
| `04_methodology.md` | 问题形式化、假设、最小充分机制、路线和风险 |
| `05_experiment_plan.md` | Claim—实验映射、基线、指标、消融、统计和停止规则 |
| `06_result_tables.md` | 预先定义的结果表、指标和数据来源 |
| `07_experiment_tracker.md` | active-run、唯一监督、累计重试与偏离决定 |
| `08_analysis.md` | 结果、不确定性、失败案例、稳健性和 Claim 状态 |
| `09_paper_plan.md` | 论文类型、叙事轴、证据位置、图表和局限 |
| `10_figure_report.md` | 图表来源、叙事角色、视觉 QA 和一致性检查 |
| `11_pre_submission_audit.md` | 引文、数值、局限、披露和可编译性审查 |
| `12_release_readiness.md` | 本地发布就绪、许可、脱敏、复现和校验和清单 |

复现单篇论文时，可在 `docs/reproduction/<paper-key>/` 增加带证据标签的复现契约；它不改变模板的 18 个核心 Skill。

阶段报告统一放在这里；深度审查临时工作区放在 `paper/review_workspace/`，不要另建顶层 `reports/` 或 `artifacts/`。

## 按阶段填写与记录归属

启动只填写 00；其他编号文件到相关阶段再填，条件性部分可标 N/A 并说明理由。保留 00–12 文件名以兼容 Skills、验证器和初始化器，不为缩短目录而合并不同生命周期的产物。

| 信息 | 唯一维护位置 | 其他文档如何使用 |
|---|---|---|
| Stage/Gate 步骤与判据 | WORKFLOW.md | 00 只记录当前状态、决定和相关 Gate 链接，不复制流程全文 |
| 个人写作默认与编辑格式规范 | WRITING_STANDARD.md | 09 实化项目结构/预算，10/11 核验 |
| 已核验期刊约束与当前编辑要求 | 02_journal_scouting.md | 09、10、11 按要求 ID 引用并记录适用性，不把参考意见当当前期刊硬规则 |
| 项目章节字数、图表目标与实际 | 09_paper_plan.md | 10、11 引用唯一预算表，不另设配额 |
| 当前阶段、下一步、授权范围 | 00_start.md | 链接状态，不另写平行交接表 |
| 数据许可、允许用途、访问与发布约束 | 00_start.md | 01、05、12 以 Dataset ID 和授权引用关联，不复制权限决定 |
| 数据来源、版本、哈希、划分与变换 | 01_data_analysis.md | 00 只链接；05 以 Dataset ID / Split ID 引用已审计划分 |
| 训练/验证/测试使用、模型选择与比较协议 | 05_experiment_plan.md | 06 定义结果呈现；07 记录偏离；08 核验实际执行 |
| Evidence / Claim 身份与当前状态 | 03_idea_report.md | 通过 ID 引用；08 保存处置依据并回填 03 |
| 方法机制与 Chain ID | 04_methodology.md | 05 设计检验，09 安排叙事，不重复定义机制 |
| 单次运行台账与原始状态 | ../experiments/registry/experiments.csv，通过 state_path 引用对应 state.json | CSV 统一登记，运行器保存原始进程/产物事实；07 的运行字段是派生绑定，冲突先核对实际进程/state.json 再修复台账；08 以实验 ID 关联 |
| 汇总指标与数值 | ../results/data/ 及可运行汇总脚本 | 06 定义表结构和引用，08 解释，不手工维护多套数值 |
| Gate 详细结论与版本 | A:03、B:05、C:08、D:09、E:10、F:11 | 00 只链接；按 WORKFLOW 的依赖变更规则重验受影响的 A–F |
| 深审问题与修订闭环 | ../paper/review_notes.md（Stage 5 时生成） | 11 记录修订后完整性检查，12 链接最终审阅版本 |

文件存在、表格标题存在或模板验证通过均不等于阶段完成。

## 每轮最小读取范围

先读 00 的当前状态、授权与下一动作，再按下表读取当前产物的相关章节和对应 Skill。无需每轮重读全部编号文档、18 个 SKILL.md 或整个结果目录。沿 Claim / Evidence / Chain / Experiment ID 定位上游记录；只有依赖变更、证据冲突或 Gate 复核时才扩展范围。

| 当前工作 | 默认读取 | 按需追溯 |
|---|---|---|
| Stage 0 启动 | 00；首次初始化读根 README | 现有项目约束与环境 |
| Stage 1A–1B 数据或期刊 | 01 或 02 | 本次数据及目标 venue 原始来源 |
| Stage 1C–1D 构思或方法 | 03 或 04；对应问题/证据 ID | 01、02 和相关原文 |
| Stage 1E 实验设计 | 05、06；03 中待检验 Claim、04 中对应机制 | 预算与数据划分记录 |
| Stage 2A–2B 运行或恢复 | 07 active-run；台账中相关实验行、配置与最新状态/日志 | 05 停止规则及失败对应代码 |
| Stage 2C 解释结果 | 08；相关 Claim、05 比较方案、06 来源索引与汇总数据 | 对应实验行、配置和异常日志 |
| Stage 3A 论文规划 | 09；03 已确认的 Claim 与 08 证据判断 | 04 机制及 02 目标要求 |
| Stage 3B 图表 | 10；09 对应图表项、结果数据和生成代码 | 图表引用的实验及机制 |
| Stage 4 写作 | 09、当前稿件章节与其证据 | 10 图表、11 当前核验项及目标格式 |
| Stage 5 深审 | 当前稿件、11、已有 review_notes 与工作区状态 | 本次问题对应的原始证据与审阅准则 |
| Stage 6 交付 | 12、最终审计与作者确认记录 | 本次打包清单、许可和目标要求 |

Gate 复核读取上表所列的 Gate 权威文件与受影响证据。阶段完成或等待条件变化后，只在 00 更新状态、产物版本/链接及下一动作；详细结论写回归属文件。发现不同记录冲突时先核对来源与版本，保留冲突及解决依据，不能用较新的文字自动覆盖原始证据。
