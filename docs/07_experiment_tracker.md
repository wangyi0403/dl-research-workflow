# 07 实验台账与监督

每次运行的配置、数据、种子、状态、日志和结果以 [experiments.csv](../experiments/registry/experiments.csv) 为准。本文件保存监督绑定、失败诊断和偏离决定，不复制“已计划/运行中/已完成”清单；项目当前阶段只在 [00_start.md](00_start.md) 维护。

本地命令可使用 `$experiment-runner` 的 `scripts/run_recorded.py`，其 `results/logs/<Experiment-ID>/state.json` 保存 PID、退出状态、配置快照与产物哈希。异常时先据此核对进程并修复 CSV，不直接重跑。

## 当前运行与唯一监督者（active-run）

每条实验链仅一行当前绑定；无运行填写 none。新运行立即更新绑定和现有监督提示词，避免监控旧任务。并行作业可属于同一实验链，由同一调度者管理。

表中的 Experiment ID、主机/PID、日志和结果路径是 CSV 及对应运行 state.json 的派生绑定快照，应优先由这些来源生成并注明核对时间；不在此独立修改运行事实。冲突时先核对实际进程与 state.json，修复 CSV 后刷新绑定。本文件独立维护的内容是监督者、健康检查、处理游标及下一动作。

| 实验链 / Experiment ID | 主机及 PID / Job ID | 唯一监督类型与 ID | 最近健康检查 | stdout / stderr / 结果路径 | 完成/失败信号 | 最近处理的终态或游标 | 下一动作与执行者 |
|---|---|---|---|---|---|---|---|

WAITING 必须对应活动对象或明确的外部条件；监督 RUNNING 无变化时静默，不自行重复提交。进程结束先核验退出状态及预期产物，再更新 CSV、分析与项目状态。换监督者记录接管结果，遵守 `WORKFLOW.md` 的运行监督与交接协议。

批次进入汇总时，按 06 的严格命令及预定 `--expect-run` 集合检查运行覆盖、配置/结果哈希与必需指标。缺失或未完成运行记为批次缺口，不以“已成功部分”宣布全批次完成；失败排除、重跑替代及其科学影响记录在下方偏离表。退出成功、证据校验通过与 Claim 成立分别判断。

## 失败诊断与重试累计

| 故障 ID / 阶段 | 失败 Experiment ID | 根因证据 | 本次最小修复与新配置/运行 ID | 累计修复次数 | 验证结果 | 继续、停止或追加授权引用 |
|---|---|---|---|---|---|---|

同一故障、同一阶段累计最多三次有新证据的修复；新运行 ID、任务或监督者不重置次数。Gate 阻断与总预算优先。失败及负结果继续保留在 CSV 中。
